In this post, I'm going to use my first contribution to an open source project as a case study, one that we'll use to learn about how to debug failed pull requests on GitHub. While this post won't cover every type of problem you could possibly run into, it will provide some fundamental steps you can take to move closer to the solutions. Let's dive in!

As [I wrote previously]({% post_url 2026-09-03-who-can-contribute-to-open-source %}), I recently started learning about open source. I did some reading, completed some tutorials, and when I felt I understood the basics, I decided to take my next steps.

While reading the documentation of an open source project I was interested in, I found a simple error in the README file.


Lessons learned:
- Before contributing to an open source project on GitHub, take some time to learn about how that project operates. While the Contributing page is a great place to start, it can also be helpful to review the workflows in Actions and read through some recent PRs, both of which will give you a better understanding of the project.
